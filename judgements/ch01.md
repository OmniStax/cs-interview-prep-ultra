## 1.1 What an algorithm is

### algorithm → Erickson `jeffe:0.1`

Ranked: 1. jeffe:0.1, 2. opendsa:AlgAnal/AnalPrelim#Problems; #Algorithms, 3. wikipedia:Algorithm
lead and #Definition, 4. wikibooks:Algorithms/Introduction, 5. wikipedia:Effective_method,
6. lt-njoroge 1.1/1.2, 7. anfp:1.1.

- **A (jeffe 0.1) vs B (OpenDSA AnalPrelim): A slightly better. B vs A: A slightly better.**
  - A puts a worked example right after the definition: "An algorithm is an explicit,
    precise, unambiguous, mechanically-executable sequence of elementary instructions...
    For example, here is an algorithm for singing that annoying song".
  - B defines problem, function, domain, range and instance before "algorithm", so it does
    define its terms first, which is good. But its five properties come with no algorithm
    shown. It also folds correctness into the definition ("It must be *correct*"), which
    clashes with A's 0.5–0.6, where correctness is something you prove.
  - Not "clearly" better. Continuity decides: every sibling in 1.1 except two goes to Erickson.
- Wikipedia's lead is encyclopedic and has no worked example in the text. Effective_method is
  computability-flavoured.
- **Checks.**
  - BottlesOfBeer mentions "beer" exactly 3n + 3 times, as 0.6 later states: three per
    verse plus three in the coda. Confirmed by counting.
  - The PDF Bottles pseudocode was read from the page render, because the `.txt` drops
    "−1".

### underspecified-algorithm → Erickson `jeffe:0.4`

  only A has.
- **Checks.**

  - B's log* 1024 = 4 is correct (10 → 3.32 → 1.73 → 0.79).
  - B's ⌈log₂ 1000⌉ = 10 bits is correct.

## 1.3 Asymptotic notation

### big-o → ODS `ods:intro#asymptotic-notation` (provisional) — **ESCALATE**

Ranked (provisional): 1. ODS, 2. aspnes-223 5.1.1–5.1.2, 3. opendsa:AlgAnal/AnalAsymptotic, 4. aspnes-202 7.1–7.4, 5. mcs2018 14.7, 6. OI Wiki complexity@5a3c3d0d 渐近符号, 7. anfp 2–3, 8. csci30 asymptotic, 9. wikipedia:Big_O_notation, 10. wikibooks DS/Asymptotic_Notation, 11. dsa-dummies.

**Reading 1. A = ODS first, then B = aspnes-223: A slightly better.**
- A says why: "Even for simple code, this quantity can be difficult to compute exactly.
  Therefore... big-Oh notation". It defines O(f(n)) as a set with c and n₀, then proves
  5n log n + 8n − 200 ≤ 13 n log n for n ≥ 2. It counts the operations in a real loop
  ("n+1 comparisons... n increments") and plots 15n against 2n log n.
- B's rule of thumb is wrong as printed: "if g(n) ≤ h(n), then g(n) + h(n) ≤ 2g(n)"
  should be 2h(n). Read after A's careful proof, that error jars.

**Reading 2. B = aspnes-223 first, then A = ODS: B slightly better.**
- B is the better "why before what": "We'll start with an example of why this is
  important". Two sorting algorithms are traced on 8 cards and costed as c·n log n and
  c₁n(n+1)/2 + c₂n. Then comes "Big-O to the rescue", and three worked c/N proofs sit
  next to the definition.
- A has its own errors in scope:
  - "O(a) ⊂ O(log n) ⊂ O(n^b) ⊂ O(c^n), for any constants a,b,c > 0" is false for
    c ≤ 1. n ∉ O(0.5ⁿ), and the ratio n/0.5ⁿ was checked to grow.
  - "if the two algorithms have demonstrably different big-Oh running times, then we can
    be certain that the one with the smaller running time will be faster" holds only for
    Θ, not O.

The two orders point in opposite directions, so this escalates.
- **Provisional winner, by continuity: ODS.** Its neighbours are logarithms (ODS),
  word-ram and running-time-guarantees (ODS), and the ODS-led chapters 2 and 3. aspnes-223
  has no neighbour here.
- OpenDSA AnalAsymptotic is third, behind both:
  - it opens leaning on a figure in another module ("Despite the larger constant for the
    curve labeled 10n in the figure above");
  - it misstates the definition ("Constant n₀ is the smallest value of n for which the
    claim of an upper bound holds true");
  - it cites "the second definition", which does not exist.

**Checks.**
- ODS: 5n log n + 8n − 200 ≤ 13 n log n holds for n = 2..99,999.
- aspnes-223: 3n + 12 < 4n for n > 100, and 4n² + 23n + 15 < 5n² for n > 100. Both
  verified.
- OI Wiki: the example "3n²+5n−3 = Θ(n²) with c₁, c₂, n₀ = 2, 4, 100" is correct. The
  multivariate example "nlog⁵n + ... = Θ(...) with c₂ = 2, n₀ = 100" is **false**: the
  ratio is 112 at n = m = 100 and still 1.7 at n = 2⁶⁰ with m = 100.
- Wikibooks has several outright errors, so it ranks low:
  - "The theta notation is denoted by Q";
  - little-o defined as "O but not Θ";
  - Ω described as "the best that can happen".

### multivariate-big-o → OpenDSA `opendsa:AlgAnal/AnalMultiple`
