## Concepts

| id | kind | tier | statement (reworded to the winning passage) | introducing span |
|---|---|---|---|---|
| `min-stack` | skill | Essential | Store each stack entry as a pair: the element and the minimum of the stack from that element down. The stack's minimum is the top pair's second value, and adding or removing an element stays O(1). | `min-stack`, "we will store them in pairs: the element itself and the minimum in the stack starting from this element and below." |
| `monotonic-queue-minimum` | idea | Essential | Keep in a deque only the elements that can still become the minimum, in nondecreasing order: before adding x, remove the trailing elements larger than x. The head is the minimum, and since each element is pushed and popped at most once, every operation is O(1) on average. Removal needs the element's value (method 1) or its index (method 2). | `min-queue`, "The key idea is to only store the items in the queue that are needed to determine the minimum." |
| `queue-from-two-stacks` | skill | Essential | Add to stack s1 and remove from stack s2, moving all of s1 into s2 (which reverses them) whenever s2 is empty. Each element is added once, transferred once and popped once, so every operation is O(1) on average; with minimum stacks, the queue's minimum is the smaller of the two stacks' minima. | `two-stack-queue`, "So we only need to learn how to simulate a queue using two stacks." |
| `sliding-window-minimum` | result | Essential | The minima of all N − M + 1 subarrays of length M of an array of length N take O(N) in all: add the first M elements to a minimum queue, then repeatedly read the minimum, add the next element and remove the oldest. | `window-minimum`, "We can use any of the three modified queues to solve the problem." |
| `nearest-smaller-element` | skill | Essential | For every position i, the nearest earlier position j with A[j] < A[i] is found in linear time by scanning with a stack: pop every top element greater than or equal to x, read the top (or none), then push x. Each pop removes an element pushed earlier, so the nested loop is linear. | `nearest-smaller`, the bold "all nearest smaller values" |
| `largest-zero-submatrix` | result | Advanced | With d[j] the nearest row at or above the current row i holding a 1 in column j, each column's best rectangle with bottom row i has top d[j] + 1, and its sides are the nearest columns left and right with a larger d, found by a stack in each direction; over all rows this is O(nm) time and O(m) memory. | `zero-submatrix`, "Find the largest submatrix consisting of only zeros (a submatrix is a rectangular area of the matrix)." |
