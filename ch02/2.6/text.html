DLList: A Doubly-Linked List

A DLList (doubly-linked list) is very similar to an SLList except that each node $u$ in a DLList has references to both the node $u.next$ that follows it and the node $u.prev$ that precedes it.

When implementing an SLList, we saw that there were always several special cases to worry about. For example, removing the last element from an SLList or adding an element to an empty SLList requires care to ensure that $head$ and $tail$ are correctly updated. In a DLList, the number of these special cases increases considerably. Perhaps the cleanest way to take care of all these special cases in a DLList is to introduce a $\htmlData{ref=dummy}{dummy}$ node. This is a node that does not contain any data, but acts as a placeholder so that there are no special nodes; every node has both a $next$ and a $prev$, with $\htmlData{ref=dummy}{dummy}$ acting as the node that follows the last node in the list and that precedes the first node in the list. In this way, the nodes of the list are (doubly-)linked into a cycle, as illustrated in Figure 3.2.

Operations on a DLList

Finding the node with a particular index in a DLList is easy; we can either start at the head of the list ($\htmlData{ref=dummy}{dummy}.next$) and work forward, or start at the tail of the list ($\htmlData{ref=dummy}{dummy}.prev$) and work backward. This allows us to reach the $\htmlData{ref=i}{i}$th node in $O(1+\min\{\htmlData{ref=i}{i},n-\htmlData{ref=i}{i}\})$ time:

def get_node(self, i):
    if i < self.n//2:
        p = self.dummy.next
        for _ in range(i):
            p = p.next
    else:
        p = self.dummy
        for _ in range(self.n, i, -1):
            p = p.prev
    return p
Node getNode(int i) {
    Node p = null;
    if (i < n / 2) {
        p = dummy.next;
        for (int j = 0; j < i; j++)
            p = p.next;
    } else {
        p = dummy;
        for (int j = n; j > i; j--)
            p = p.prev;
    }
    return p;
}
DLList<T>::Node* DLList<T>::getNode(int i) {

}

The running time of these operations is dominated by the time it takes to find the $\htmlData{ref=i}{i}$th node, and is therefore $O(1+\min\{\htmlData{ref=i}{i},n-\htmlData{ref=i}{i}\})$.

Adding and Removing

If we have a reference to a node $\htmlData{ref=w}{w}$ in a DLList and we want to insert a node $\htmlData{ref=u}{u}$ before $\htmlData{ref=w}{w}$, then this is just a matter of setting $\htmlData{ref=u}{u}.next=\htmlData{ref=w}{w}$, $\htmlData{ref=u}{u}.prev=\htmlData{ref=w}{w}.prev$, and then adjusting $\htmlData{ref=u}{u}.prev.next$ and $\htmlData{ref=u}{u}.next.prev$. (See Figure 3.3.) Thanks to the dummy node, there is no need to worry about $\htmlData{ref=w}{w}.prev$ or $\htmlData{ref=w}{w}.next$ not existing.

Now, the list operation $add(i,x)$ is trivial to implement. We find the $\htmlData{ref=i}{i}$th node in the DLList and insert a new node $\htmlData{ref=u}{u}$ that contains $x$ just before it.

The only non-constant part of the running time of $add(i,x)$ is the time it takes to find the $\htmlData{ref=i}{i}$th node (using $getNode(i)$). Thus, $add(i,x)$ runs in $O(1+\min\{\htmlData{ref=i}{i}, n-\htmlData{ref=i}{i}\})$ time.

Removing a node $\htmlData{ref=w}{w}$ from a DLList is easy. We only need to adjust pointers at $\htmlData{ref=w}{w}.next$ and $\htmlData{ref=w}{w}.prev$ so that they skip over $\htmlData{ref=w}{w}$. Again, the use of the dummy node eliminates the need to consider any special cases:

def _remove(self, w):
    w.prev.next = w.next
    w.next.prev = w.prev
    self.n -= 1
void remove(Node w) {
    w.prev.next = w.next;
    w.next.prev = w.prev;
    n--;
}
void DLList<T>::remove(Node *w) {
    w->prev->next = w->next;
    w->next->prev = w->prev;
    delete w;
    n--;
}
_remove(w) {
  w.prev.next = w.next;
  w.next.prev = w.prev;
  this.n--;
}

Now the $remove(i)$ operation is trivial. We find the node with index $\htmlData{ref=i}{i}$ and remove it:

def remove(self, i):
    if i < 0 or i >= self.n: raise IndexError()
    self._remove(self.get_node(i))
T remove(int i) {
    Node w = getNode(i);
    remove(w);
    return w.x;
}
T DLList<T>::remove(int i) {
    Node *w = getNode(i);
    T x = w->x;
    remove(w);
    return x;
}
remove(i) {
  const w = this.getNode(i);
  this._remove(w);
  return w.x;
}

Again, the only expensive part of this operation is finding the $\htmlData{ref=i}{i}$th node using $getNode(i)$, so $remove(i)$ runs in $O(1+\min\{\htmlData{ref=i}{i}, n-\htmlData{ref=i}{i}\})$ time.

Summary

The following theorem summarizes the performance of a DLList:

Theorem

A DLList implements the List interface. In this implementation, the $get(i)$, $set(i,x)$, $add(i,x)$ and $remove(i)$ operations run in $O(1+\min\{\htmlData{ref=i}{i},n-\htmlData{ref=i}{i}\})$ time per operation.

It is worth noting that, if we ignore the cost of the $getNode(i)$ operation, then all operations on a DLList take constant time. Thus, the only expensive part of operations on a DLList is finding the relevant node. Once we have the relevant node, adding, removing, or accessing the data at that node takes only constant time.

This is in sharp contrast to the array-based List implementations of Section 2.2; in those implementations, the relevant array item can be found in constant time. However, addition or removal requires shifting elements in the array and, in general, takes non-constant time.

For this reason, linked list structures are well-suited to applications where references to list nodes can be obtained through external means.
